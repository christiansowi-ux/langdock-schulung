Brücke zu Lektion 3 – „LLMs unter der Lupe“
In der Lektion ging es darum, was im Hintergrund passiert, wenn man in Langdock eine Anfrage stellt: vom Browser über Verschlüsselung, Load Balancer und API bis ins Rechenzentrum, wo die Antwort Token für Token entsteht. Heute macht man das sichtbar – und lernt, warum ein guter Prompt genau hier ansetzt.

Wissen kompakt: Die Reise einer KI-Anfrage

Die Frage aus der Lektion: Was passiert eigentlich im Hintergrund, wenn man in Langdock eine Anfrage abschickt? Fünf Stationen, in Sekundenbruchteilen.

1Die AnfrageMan tippt in einer Web-App oder App, z. B. Langdock. Sichtbar ist nur die Oberfläche – die „Intelligenz“ läuft woanders. Die Nachricht verlässt das Gerät.
2TransportDas Gerät schickt die Anfrage (Request) ins Internet – verschlüsselt über HTTPS/SSL – zum Modellanbieter.
3Load BalancerVerteilt alle eingehenden Anfragen auf freie Server – wie ein Weichenstellwerk am Bahnhof. Sonst wäre alles bei Millionen Anfragen überlastet.
4APIDie Schnittstelle: leitet die Anfrage an das richtige Modell, übersetzt sie in ein passendes Format und bringt die Antwort zurück.
5Rechenzentrum
  1. Kontext zusammenbauen
  2. Tokenisierung (CPU)
  3. Laden in den GPU-Speicher
  4. Embedding: Bedeutung als Vektoren
  5. Rechnen auf GPUs/TPUs
  6. Token für Token, oft als Stream
  7. Cache wird geleert

Die Begriffe in einem Satz

BegriffKurz erklärt
RequestFachbegriff für eine Anfrage an einen Server („IT-Sprech“).
HTTPS / SSLVerschlüsselte, sichere Datenübertragung im Internet – geschützt vor fremdem Zugriff.
Load BalancerVerteilt Anfragen auf freie Server, damit nichts überlastet.
APISchnittstelle, über die Programme miteinander sprechen – hier: das Gerät mit der KI.
TokenTextbaustein – ein Wort, ein Wortteil oder ein Zeichen. Das Modell liest und schreibt in Tokens.
Embedding / VektorEine lange Zahlenreihe, die Bedeutung abbildet: Ähnliche Bedeutungen liegen nah beieinander.
GPU / TPUSpezialchips, die sehr viele Rechnungen gleichzeitig ausführen.
StreamDie Antwort wird Stück für Stück live übertragen, während sie entsteht.
KontextAlles, was das Modell für diese eine Anfrage bekommt: Prompt, bisheriger Chatverlauf, Anhänge, Anweisungen.

Zum Nachschauen (aus der Lektion): „Large Language Models explained briefly“ (7:58 Min) und „How AI Turns Words Into Vectors: Embeddings“ (3:35 Min) – beide auf YouTube, englisch; die Untertitel lassen sich auf Deutsch umstellen.

Merke: Das Modell sieht nur, was im Kontext steht. Alles andere – interne Daten, Absprachen, der Tonfall des Hauses – existiert für das Modell nicht. Fehlt etwas, wird es nicht nachgefragt, sondern plausibel ergänzt.

4Kontrollquiz: richtig oder falsch?
Aussagerichtigfalsch
a) Die Anfrage wird verschlüsselt (HTTPS/SSL) zum Modellanbieter übertragen.
b) Der Load Balancer sorgt dafür, dass die Antwort inhaltlich besser wird.
c) Die API übersetzt die Anfrage in ein Format, das das Modell versteht, und bringt die Antwort zurück.
d) Das Modell berechnet die ganze Antwort auf einmal und schickt sie erst dann los.
e) Nach der Anfrage bleiben die eigenen Daten im GPU-Cache für andere Nutzende liegen.
f) Vor dem Rechnen wird der Text in Tokens zerlegt und als Zahlen (Vektoren) eingeordnet.
Kontrolllösung – Heft drehen

Richtig: a, c, f. Falsch: b – der Load Balancer verteilt nur Anfragen auf freie Server; d – die Antwort entsteht Token für Token und wird oft live als Stream übertragen; e – nach der Anfrage wird der GPU-Cache für andere Anfragen geleert.

Aufgabe 2

Tokens und Vektoren zum Anfassen

20 Min

Ziel: Verstehen, dass ein Modell nicht in Wörtern, sondern in Tokens und Zahlen rechnet – und was daraus im Alltag folgt.

1Tokens sichtbar machen
Prompt Neuer Chat

Zerlege den Satz „Der Glasfaserhausanschluss wird bis Donnerstag freigeschaltet.“ ungefähr so in Tokens, wie ein Sprachmodell es tun würde. Markiere die Grenzen mit einem senkrechten Strich. Erkläre kurz, warum lange Fachwörter oft in mehrere Tokens zerfallen.

Hinweis: Ein Modell sieht seine eigenen Token-Grenzen nicht direkt. Die Antwort ist eine gute Annäherung, keine exakte Messung.

2Der Buchstaben-Test
Prompt Neuer Chat – erst Thinking aus, dann Thinking an

Wie oft kommt der Buchstabe „s“ im Wort „Glasfaserhausanschluss“ vor? Antworte nur mit der Zahl.

DurchgangAntwort von LangdockSelbst nachgezählt
Thinking aus
Thinking an
Kontrolllösung – Heft drehen

6-mal „s“: „Glas“ (1) + „faser“ (1) + „haus“ (1) + „anschluss“ (3). Warum Modelle sich hier verzählen können: Sie sehen Token-Stücke wie „Glas“, „faser“, „haus“, „anschluss“, nicht einzelne Buchstaben. Mit Thinking zählt ein Modell Schritt für Schritt – deshalb klappt es dann oft.

3Vektoren: Wie nah liegen Bedeutungen beieinander?

Erst selbst schätzen (0 = nichts gemeinsam, 10 = fast dasselbe), dann Langdock fragen.

Prompt Neuer Chat

Stell dir vor, jedes Wort wäre ein Punkt in einem Bedeutungsraum, wie bei Embeddings. Wie nah liegen diese Paare beieinander, auf einer Skala von 0 (nichts gemeinsam) bis 10 (fast dasselbe)? Glasfaser – Breitband, Glasfaser – Kupferkabel, Glasfaser – Urlaubsantrag, Tarif – Vertrag. Begründe jede Zahl in einem Satz.

WortpaarEigene SchätzungLangdock
Glasfaser – Breitband
Glasfaser – Kupferkabel
Glasfaser – Urlaubsantrag
Tarif – Vertrag
Merke: Das ist ein Gedankenexperiment – echte Embeddings sind Zahlenreihen mit Hunderten bis Tausenden Stellen. Das Prinzip stimmt aber: Weil „Glasfaser“ und „Breitband“ nah beieinander liegen, findet ein Modell die passende Stelle im Dokument auch dann, wenn dort das andere Wort steht.
