1 · Verstehen

Eine Regel. Mehr musst du dir zunächst nicht merken.

01 / 23 · Modul 2 · Lektion 1 · Tag 3/4 · Mittwoch, 28.10.2026 · Dein Ziel am 28.10.2026

Mittwoch: Nur Fertiges darf weiter

Heute machen wir es kleiner: Du gibst nur ein Wort ein. Steht dort FERTIG, darf Make einen nächsten Schritt ausführen. Steht dort ENTWURF, stoppt der Weg.

  1. Ein Wort: FERTIG oder ENTWURF
  2. Eine Regel prüft das Wort
  3. Weiter oder Stopp

Das ist deine einzige Hauptaufgabe

Baue eine kleine Freigabe-Ampel. Du brauchst zwei Bausteine und eine Regel dazwischen. Kein JSON, keine KI und keine neue Anmeldung.

Wichtig

Unsere Ampel ist eine Übung mit einem erfundenen Status. Sie veröffentlicht nichts und ersetzt keine echte Freigabe durch eine zuständige Person.

Wenn das klappt, wähle höchstens ein Extra: eine Idee in Google Sheets speichern oder eine Schlagzeile holen. Beide stehen mit eigener kurzer Anleitung im Bonus. Du musst nicht alles bauen.

Ein Filter ist wie eine kleine Tür

Stell dir eine Tür mit einem Schild vor: „Nur Fertiges“. Die Tür schaut auf deinen Status. Bei FERTIG geht sie auf. Bei ENTWURF bleibt sie zu. So arbeitet unser Filter.

Wort in MakeWas es heute bedeutet
SzenarioDein ganzer Ablauf.
ModulEin Baustein, als Kreis dargestellt.
FilterDie Regel auf der Verbindung zwischen zwei Bausteinen.
Run onceDu startest einen einzelnen Versuch selbst.
Kurz prüfen

Wenn ENTWURF gestoppt wird, hat der Filter seine Aufgabe erfüllt. Nicht jeder Stopp ist ein Fehler.

Die kleine Ampel darunter ist nur zum Ausprobieren im Browser. Sie startet nichts in Make und kostet keine Make-Credits.

Erst hier ohne Make ausprobieren

Wähle einen Status. Die Regel lautet: Nur FERTIG darf weiter.

Das ist nur eine Lernhilfe im Browser. Kein Make-Aufruf, keine Veröffentlichung und kein Creditverbrauch.

2 · Nachbauen

Vier kleine Schritte mit bekannten Bausteinen.

03 / 23 · Modul 2 · Lektion 1 · Tag 3/4 · Mittwoch, 28.10.2026 · Ganz einfach

Schritt 1: Einen Status bereitstellen

Mach das

  1. Öffne in Make ein neues eigenes Szenario. Nenne es M2-03 Freigabe-Ampel.
  2. Wähle über das Plus Tools → Set variable.
  3. Trage bei Variable name status ein.
  4. Trage bei Variable value FERTIG ein. Falls eine Lebensdauer gefragt wird: One execution.
  5. Bestätige, speichere und klicke einmal auf Run once.
  6. Öffne die Ausgabe am Baustein. Dort muss FERTIG stehen.
FeldEingabe
Variable namestatus
Variable valueFERTIG
Wichtig

Die automatische Planung bleibt ausgeschaltet. Dieser erste Test stellt nur deinen Wert bereit. Du hast noch nichts verschickt.

04 / 23 · Modul 2 · Lektion 1 · Tag 3/4 · Mittwoch, 28.10.2026 · Ganz einfach

Schritt 2: Die Meldung vorbereiten

Mach das

  1. Ergänze rechts einen zweiten Baustein: Tools → Compose a string.
  2. Tippe in Text: Beitrag zur Planung bereit. Status: und danach ein Leerzeichen.
  3. Wähle dahinter den Wert status aus dem ersten Baustein aus.
  4. Bestätige und speichere.

So sieht es richtig aus

Dein Text enthält den festen Satz und ein ausgewähltes farbiges Feld. Dieses Feld übernimmt den Status vom ersten Baustein.

Wichtig

FERTIG hier nicht noch einmal fest eintippen. Der Status soll aus dem ersten Baustein kommen. Der Filter folgt im nächsten Schritt.

05 / 23 · Modul 2 · Lektion 1 · Tag 3/4 · Mittwoch, 28.10.2026 · Ganz einfach

Schritt 3: Genau eine Regel einsetzen

Mach das

  1. Klicke auf die Verbindung zwischen den beiden Bausteinen.
  2. Gib dem Filter den Namen Nur Fertiges.
  3. Wähle links das Feld status aus dem ersten Baustein.
  4. Wähle als Textvergleich Equal to. Das heißt „ist gleich“.
  5. Tippe rechts FERTIG ein.
  6. Speichere den Filter und den Ablauf.
  1. status aus Baustein 1
  2. Textvergleich: Equal to
  3. Fester Vergleichswert: FERTIG
Wichtig

Das ist schon die ganze Regel. Kein zweites Feld, kein AND, kein Router. Je nach Sprache kann „Equal to“ als „Gleich“ erscheinen. [M9]

06 / 23 · Modul 2 · Lektion 1 · Tag 3/4 · Mittwoch, 28.10.2026 · Ganz einfach

Schritt 4: Einmal weiter, einmal stoppen

Erster Test: FERTIG

Speichere und starte den ganzen Ablauf mit Run once. Öffne die neue Ausgabe des zweiten Bausteins. Erwartet: Beitrag zur Planung bereit. Status: FERTIG

Zweiter Test: ENTWURF

Öffne den ersten Baustein. Ändere nur Variable value von FERTIG zu ENTWURF. Speichere und starte erneut. Jetzt soll der Filter den Weg stoppen. Der zweite Baustein erzeugt in diesem Lauf keine neue Meldung.

Dein TestwertWas passieren soll
FERTIGDie Meldung wird im zweiten Baustein erzeugt.
ENTWURFDer Weg stoppt vor dem zweiten Baustein.
Kurz prüfen

Öffne den aktuellen Lauf. Eine alte Ausgabe mit FERTIG ist kein Ergebnis des neuen ENTWURF-Tests.

Wichtig

Geplant: 1 Credit für die Einzelprobe, 2 für den Weiter-Test und 1 für den Stopp-Test. Zusammen ungefähr 4 Credits. Der Filter selbst kostet keine Credits; weitere Starts können zusätzliche verbrauchen. Es zählt die Anzeige deines Kontos. [M2]

So passt es zu deinem Bereich

Video: „Drehplan zur Prüfung bereit“. Vertrieb: „Angebotsentwurf zur Prüfung bereit“. Team: „Teaminfo zur Prüfung bereit“. Dafür änderst du nur den festen Text im zweiten Baustein. Die Regel bleibt gleich.

Ohne neue Anmeldung: eine Schlagzeile holen

11 / 23 · Modul 2 · Lektion 1 · Tag 3/4 · Mittwoch, 28.10.2026 · Freiwillig: keine neue Anmeldung

Extra 1: Eine frische Schlagzeile holen

Nützlich für ein kleines Ideen- oder Nachrichtenboard: Make liest eine Überschrift und einen Link. Keine zusätzliche Anmeldung. Als Beispiel verwenden wir den öffentlichen deutschsprachigen tagesschau-Feed. Eine Schlagzeile ist noch kein geprüfter eigener Social-Media-Text.

Mach das

  1. Erstelle ein eigenes neues Szenario M2-03 Schlagzeile. Zeitplan aus lassen.
  2. Wähle RSS → Retrieve RSS Feed Items. Verwende Retrieve, nicht Watch.
  3. Füge die Feed-Adresse unten in URL ein. Setze Maximum number of returned items auf 1. Datumsfilter für diesen Versuch leer lassen.
  4. Speichere und führe zunächst nur diesen Baustein mit Run once aus.
  5. Öffne die Ausgabe. Suche nach der Überschrift und dem Link zum Artikel. Die Überschrift kann täglich wechseln.
RSS-Adresse zum Einfügen in URL
https://www.tagesschau.de/infoservices/alle-meldungen-100~rss2.xml
Kurz prüfen

Ist eine echte Überschrift mit passendem Link angekommen? Die Adresse wurde am 27.10.2026 direkt gelesen: HTTP 200 und gültiger RSS-Feed. Das ist kein Test des Moduls in deinem Make-Konto.

Wichtig

Nur ein Artikel pro Versuch. So vermeidest du eine große Liste. Geplanter Verbrauch für einen einfachen Einzelabruf: ungefähr 1 Credit. Feed-Anbieter können ihr Angebot später ändern. [R1, N1]

12 / 23 · Modul 2 · Lektion 1 · Tag 3/4 · Mittwoch, 28.10.2026 · Freiwillig: zweiter kleiner Schritt

Aus der Schlagzeile wird dein Lesezettel

Mach das

  1. Hänge Tools → Compose a string hinter den erfolgreich getesteten RSS-Baustein.
  2. Tippe Lesetipp: und ein Leerzeichen. Wähle das Feld für die Überschrift aus der RSS-Ausgabe, häufig Title.
  3. Füge eine neue Zeile hinzu und wähle den Artikel-Link aus derselben Ausgabe.
  4. Speichere und starte beide Bausteine einmal.
  5. Prüfe, ob die Überschrift und der Link im fertigen Text zusammenpassen.

Jetzt hast du einen kleinen wiederverwendbaren Lesezettel statt einer abgeschriebenen Überschrift. Für andere Themen kannst du später einen passenden öffentlichen RSS-Feed einsetzen.

Wichtig

Die Ausgabe wird nicht automatisch verschickt oder veröffentlicht. Dieselbe Meldung kann bei erneutem Abruf wiederkommen: Wir bauen hier keinen Speicher für bereits gelesene Artikel. Mit Einzelprobe und einem Zweierlauf zusammen geplant ungefähr 3 Credits.

Mit vorhandenem Google-Konto: eine Idee speichern

Extra 2: Eine Idee in Google Sheets sichern

Hier entsteht wirklich eine gespeicherte Tabellenzeile. Wähle dieses Extra nur, wenn du bereits ein eigenes Google-Konto hast und es mit Make verbinden möchtest. Sonst nimm das RSS-Beispiel.

Mach das

  1. Erstelle in Google Sheets eine neue eigene Tabelle Ideenparkplatz. Schreibe in A1 Idee und in B1 Bereich.
  2. Lege in Make ein neues manuelles Szenario M2-03 Idee sichern an. Erster Baustein: Tools → Set variable, Name idee, Wert Teamfoto für die Website. Einmal allein testen.
  3. Ergänze Google Sheets → Add a Row. Verbinde dein eigenes Google-Konto. Wähle die neue Tabelle und ihr Tabellenblatt; Table contains headers: Yes.
  4. Wähle beim Feld Idee den Wert idee aus dem ersten Baustein. Trage bei Bereich fest Marketing ein.
  5. Speichere und starte beide Bausteine einmal mit Run once.
  6. Öffne Google Sheets. Unter den Überschriften muss deine neue Zeile stehen.
Kurz prüfen

Die Idee wird vom ersten Baustein in deine neue Tabelle übertragen. Später änderst du nur den Wert im ersten Baustein. Jeder weitere Start ergänzt eine Zeile; er ersetzt die vorherige nicht.

Wichtig

Einzelprobe und kompletter Zweierlauf: geplant ungefähr 3 Credits. Kontoverbindung kann extra Zeit brauchen. Werden zusätzliche Technik oder Freigaben verlangt, wähle das RSS-Extra. Keine Bezahl- oder Cloud-Entwickler-Einrichtung für diese Übung anfangen. [G1, G2]

Die heutigen Originalfolien eingeordnet

17 · Webhooks

Ein Webhook meldet ein Ereignis an eine vereinbarte Adresse, ähnlich einer Klingel. Polling fragt regelmäßig nach. Ein API-Aufruf kann Daten lesen oder schreiben. Webhooks können schnell starten, aber Warteschlangen und Verarbeitung brauchen ebenfalls Zeit. Heute richten wir keinen öffentlichen Eingang ein.

18 · Große Formularaufgabe

Die große Originalübung verbindet Formular, KI-Einordnung, Bestätigungsmail und zuständige Teams. Tally, Modell-API, Microsoft 365 und HubSpot benötigen eigene passende Zugänge. Diese Kette ist kein Pflichtprojekt für den Einstieg und nicht automatisch vollständig durch Make Free bezahlt.

19 · Formular und Start

Das Tally-Formular sammelt Vorname, Nachname, E-Mail, Anliegen und Nachricht. Die Kategorien sind Angebot/Projekt, Support/Hilfe, Feedback/Beschwerde, Partnerschaft/Kooperation und Sonstiges. Ein neuer Formulareingang kann den Ablauf starten. Heute genügt ein selbst gesetzter Teststatus.

19 / 23 · Tag 3/4 · Originalfolien 20, 21, 22

Die heutigen Originalfolien eingeordnet

20 · Systemprompt und KI-Modul

Die Vorlage holt Testdaten, gibt der KI Regeln und verlangt Antwortfelder für betreff, body_text, kategorie und prioritaet. Beispiele helfen beim Prüfen. Konkreter Modellname, Modulnummer und Einstellung aus Juli 2026 müssen beim Einsatz neu geprüft werden. Ein JSON-Wunsch allein garantiert keine richtige Antwort.

21 · JSON, Mail und Router

Parse JSON würde die Modellantwort in Felder aufteilen. Danach kann man mit erlaubten Angaben eine Mail vorbereiten und Routen wählen. Eine KI-Antwort soll vor dem echten Versand geprüft werden. Die heutige Ampel zeigt nur den kleinen Teil „darf weiter oder soll stoppen“.

22 · Zuständige Wege

Die Vorlage verteilt nach Angebot, Support, Feedback/Beschwerde, Partnerschaft, Sonstiges und zusätzlich Spam. Vertrieb könnte einen Kontakt und eine Aufgabe in HubSpot bekommen; Support eine interne Nachricht. Das benötigt weitere Konten, passende Prioritätswerte und Regeln für Zweifelsfälle. Normale Router-Routen laufen nacheinander.

20 / 23 · Tag 3/4 · Originalfolien 23, 28, 29

Die heutigen Originalfolien eingeordnet

23 · Tests und Dokumentation

Die große Kette würde mit Angebot, Support, Beschwerde und widersprüchlichen Angaben getestet. Verlauf, Verbrauch, Routing und Ergebnisse müssten dokumentiert werden. Heute dokumentierst du nur zwei kleine Fälle: FERTIG geht weiter, ENTWURF stoppt. Aktivieren einer fremden großen Vorlage ist nicht nötig.

28 · Filter und Router

Ein Filter ist eine Tür mit einer Regel. Ein Router ist eine Weggabelung. Beide steuern, welche Schritte ausgeführt werden. Wenn ein Filter stoppt, kann er unnötige Folgeschritte vermeiden. Für den ersten einfachen Versuch reicht unsere einzelne Tür.

29 · Operatoren

Vergleiche sind Fragen wie gleich, ungleich, größer, kleiner oder enthält. Zahlenvergleiche brauchen passende Zahlen. AND verlangt alle verbundenen Regeln; OR mindestens eine. Wir verwenden nur den einfachen Textvergleich status ist gleich FERTIG.

30 · Prompt-Rollen

System-Regeln geben einer passenden KI-Schnittstelle die Grundrichtung. User ist die konkrete Frage oder Eingabe. Assistant ist die Antwort im Verlauf. Man unterscheidet diese Rollen, damit Regeln, Eingaben und Antworten nicht durcheinandergeraten. Für die Ampel brauchst du kein KI-Modell.
